# Full-pass sweep — 2026-11-12

## Objective

Audit and repair the DeckOps application across correctness, failure handling,
UI, and controller/keyboard UX. Preserve existing game, Steam, save, and update
safety guarantees; add focused regressions rather than rewriting working flows.

## Passes and coverage

| Pass | Scope | Checks |
| --- | --- | --- |
| 1. Baseline and startup | `main.py`, logging/crash handling, identity, launcher/install/prelaunch shell, update journal and recovery | Ruff, Python/shell syntax, full tests, interrupted-update and offline startup behavior |
| 2. Application workflows | Detection, configuration, networking, client install/update, Proton, depot downgrade, offline mode | Error propagation, cancellation, retries, partial results, source/mode consistency |
| 3. Data safety | Steam VDF/shortcut/controller edits, game configs, save backup/restore, uninstall | Atomic writes, backups/ledgers, cancellation before destructive changes, temporary-root tests |
| 4. UI and UX | Shared Qt helpers, setup, selection, installation, library, settings, field guide, updates | PyQt6/PyQt5, controller-only navigation, busy states, readable feedback, small-window layouts, accessible names |
| 5. Verification | All changed paths and their callers | New regressions, full suite, lint, shell syntax, offscreen UI smoke and screenshots |

## Execution rules

- Reproduce a defect or identify a concrete failing path before changing it.
- Fix the cause, not just the visible symptom; keep changes scoped to the sweep.
- Use existing `unittest` conventions and temporary HOME/Steam/game/config roots.
- Never run an actual install, uninstall, Steam edit, or save restore against user data.
- Keep Qt imports behind `qt.py`; preserve PyQt5 fallback and Deck control sizes.
- Do not change release tags/assets, branch identity, or the tracked Windows binary
  unless a source change requires its documented rebuild (which needs Windows).
- Record hardware-dependent checks honestly; offscreen tests are not a Steam Deck test.

## Findings fixed

| Area | Defect / failing path | Fix | Regression |
| --- | --- | --- | --- |
| FOV watcher | Empty saved `DECKOPS_LD_PRELOAD` / `DECKOPS_LD_LIBRARY_PATH` values let ambient helper libraries leak into the managed child; this reproduced the baseline test failure. | `_child_env()` now unsets the ambient variable when the saved value is empty, while still restoring nonempty Steam values. | `tests/test_sweep7_core.py` |
| Config cache | Missing/corrupt config paths could leave a stale cached setup; a corrupt file that could not be moved aside could later be overwritten with defaults. | Invalidates cache on missing/corrupt/racing-disappearance paths; marks the file unreadable if move-aside fails so setters refuse to overwrite it. | `tests/test_sweep7_core.py` |
| Startup component install | Zenity cleanup after a successful PyQt6 component install could raise `BrokenPipeError` / `ProcessLookupError` and turn success into a startup crash. | Cleanup closes/terminates/waits defensively and ignores already-exited dialog errors. | `tests/test_sweep7_core.py` |
| Settings tasks | A Settings task could start over another busy operation; worker spawn failure could leave the task slot, disabled buttons, and sleep lock held; player-name save failure could still look successful. | Busy refusal, shared spawn-failure release path, and explicit name-save failure handling. | `tests/test_sweep7_ui.py` |
| DeckOps update check | Double-click could start multiple checks; a failed/offline re-check could leave the button wired to apply an earlier advertised update; spawn failure could leave the button disabled. | Reentrancy guard, failure signal path, and button rebinding on every non-update result. | `tests/test_sweep7_ui.py` |
| Library / selection scans | Thread-spawn failure could crash card construction or leave scanning UI stuck; optional cover fetch could break the Library. | Recoverable scan failure states and optional cover-fetch guard. | `tests/test_sweep7_ui.py` |
| Library deadzone pass | Background deadzone writes did not hold the shared busy flag, so another task could race the same game configs. | Takes/releases the inhibit busy flag around the pass, including spawn failure. | `tests/test_sweep7_ui.py` |
| Install / update screens | Re-entry could restart running work; worker spawn failure could leave the screen running forever; MW3 verification dialog errors were unhandled. | Start guards, explicit spawn-failure completion, and guarded verification prompt/Steam launch. | `tests/test_sweep7_ui.py`, adjusted `tests/test_sweep6_install_ui.py` |
| Save restore offer | Restore could start over another busy operation; successful restore hid only the actions, leaving the section header/body behind. | Busy refusal and hiding the whole restore section on success. | `tests/test_sweep7_ui.py` |
| Reset config | A failed config reset could still restart setup and claim success. | Reports the failure and does not navigate/reload. | `tests/test_sweep7_ui.py` |
| Offline Mode removal | Destructive removal confirmation defaulted to Yes. | Removal defaults to No; addition still defaults to Yes. | `tests/test_sweep7_ui.py` |
| Save backup commit | After an interrupted backup swap, the next failed commit could delete the only remaining complete backup in `.old`. | Recovers an interrupted `.old` swap before starting a new commit. | `tests/test_sweep7_data_safety.py` |
| Accessibility | Dynamic button text changes could leave stale accessible names. | Accessible names updated with update notice, self-update, FPS cap, music, and details-toggle labels. | `tests/test_sweep7_ui.py` |
